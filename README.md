# Twig

생각을 빠르게 수집하고 하위 가지로 발전시키는 Apple 전용 영감 메모앱입니다.

## 구현 범위

- 폴더 생성, 이름 수정, 기본·크림·핑크·블루·그린·다크 강조 테마
- 제목 없는 빠른 입력, 기본 수집함 저장, 기존/새 폴더 선택
- 최상위 메모와 하위 가지, 접기/펼치기, 형제 순서 이동, 부모/폴더 변경
- 단문·장문 편집, 선택적 제목, 태그, 작성/수정/사용자 지정 날짜
- 키워드 + 태그 + 날짜 범위 검색 (폴더별 또는 전체)
- 로컬 자동 저장, 저장 실패 안내 및 재시도, 편집 기록 복구
- 폴더/가지 휴지통 이동 및 복구 (자동 영구 삭제 없음)
- 최근 수정한 폴더, 오늘 다시 볼 영감, 무작위 다시 보기
- 휴지통과 편집 기록을 포함하는 Markdown 텍스트 내보내기
- iPhone의 단계별 탐색, iPad/Mac의 3열 탐색, 시스템 라이트/다크 모드
- 앱 안에서 `⌘N`으로 빠른 입력 (전역 Mac 단축키는 후속 기능)

**검증 상태:** Windows에서 구현했습니다. 이 환경에는 Swift/Xcode가 없어 Apple 빌드, Swift 테스트, UI, iCloud 동기화를 실행하지 못했습니다. 출시 가능한 검증 완료 빌드라는 뜻은 아닙니다.

## Mac에서 실행

1. 기존 프로젝트를 열 수 있는 Xcode에서 `twig.xcodeproj`를 엽니다.
2. Scheme은 `twig`, 실행 대상은 iPhone/iPad Simulator 또는 `My Mac`을 선택합니다.
3. `⌘B`로 빌드하고 `⌘R`로 실행합니다.
4. 실기기 실행 시 Signing & Capabilities에서 본인의 Team과 고유 Bundle Identifier를 지정합니다.

최소 지원 버전은 iOS/iPadOS 18, macOS 15로 설정했습니다. 원본 Xcode 프로젝트 형식(`objectVersion = 90`)은 유지했습니다. 설치된 Xcode가 프로젝트 형식을 지원하지 않으면 해당 프로젝트를 생성한 버전 이상의 Xcode에서 열어야 합니다.

터미널에서 서명 없이 컴파일만 확인하려면:

```sh
xcodebuild -project twig.xcodeproj -scheme twig -destination 'generic/platform=iOS Simulator' -derivedDataPath DerivedData build CODE_SIGNING_ALLOWED=NO
xcodebuild -project twig.xcodeproj -scheme twig -destination 'platform=macOS' -derivedDataPath DerivedData build CODE_SIGNING_ALLOWED=NO
```

데이터·트리·날짜 테스트는 프로젝트 루트에서 실행합니다. 이 패키지는 앱이 사용하는 실제 모델과 서비스를 직접 컴파일합니다.

```sh
swift test
```

SwiftData를 사용하는 테스트이므로 macOS에서 Swift 6 이상이 필요합니다. Xcode 앱의 Scheme에는 별도 테스트 타깃을 추가하지 않았습니다. `⌘U` 대신 위 명령을 사용하거나 `Package.swift`를 Xcode에서 따로 열어 테스트하세요.

## 처음 사용하기

1. 왼쪽/첫 화면의 **새 폴더**로 프로젝트를 만듭니다.
2. **빠른 영감 기록**을 누르고 본문을 입력합니다. 즉시 수집함에 로컬 저장됩니다.
3. 폴더를 선택하면 트리가 표시됩니다. `+`는 최상위 메모를 만듭니다.
4. 메모를 열고 `+`로 하위 가지를 만듭니다. `…` 메뉴에서 부모/폴더 이동, 순서 이동, 기록 복구를 할 수 있습니다.
5. 목록의 메모/폴더를 길게 누르거나 Mac에서 우클릭하면 관련 메뉴가 나타납니다.
6. 검색창에 `#앱 아이디어`처럼 입력하고 날짜 필터를 조합합니다.

## 코드 읽는 순서

| 파일 | 역할 | JavaScript/React와 비교 |
| --- | --- | --- |
| `MyApp.swift` | 앱 진입점, 저장소 초기화 | 앱 bootstrap |
| `Services/StorageConfiguration.swift` | 로컬 저장 및 선택적 CloudKit 설정 | DB 연결 설정 |
| `Models/` | 저장되는 폴더·메모·편집 기록 | DB 모델 |
| `ContentView.swift` | 폴더/메모 선택 및 화면 배치 | 최상위 컴포넌트와 선택 state |
| `Views/` | 목록, 편집, 폼 | 기능별 React 컴포넌트 |
| `Services/NoteStore.swift` | 저장, 가지 이동, 삭제, 복구 | 공유 데이터 조작 함수 |
| `Logic/` | 순환에 안전한 트리 탐색, 날짜 변환 | 순수 함수 모듈 |

- `@State`: 화면이 소유하는 값. React의 `useState`와 비슷합니다.
- `@Binding`: 부모 상태를 자식에서 읽고 바꾸는 연결입니다.
- `@Query`: SwiftData를 조회하고 변경을 화면에 반영합니다.
- `@Environment(\.modelContext)`: 상위 화면이 제공한 저장 컨텍스트를 가져옵니다.
- `@Observable`: 속성이 바뀌면 사용하는 화면이 갱신되도록 합니다.
- `@MainActor`: UI와 저장 작업을 메인 액터에서 순차적으로 수행하게 합니다.
- `UUID?`: 값이 없을 수도 있는 ID입니다. `nil`은 JavaScript의 `null`과 비슷합니다.
- `guard`: 조건이 맞지 않을 때 함수를 일찍 종료합니다.
- `@Model`: SwiftData가 클래스 인스턴스를 저장하도록 지원하는 매크로입니다.

## 데이터 정책

- 기존 `InspirationFolder`의 필드는 유지하고 새 모델만 추가했습니다. 기존 저장소를 지우거나 메모리 저장소로 몰래 대체하는 복구 코드는 없습니다.
- 폴더와 부모는 UUID로 연결합니다. 수집함은 폴더 ID가 없는 상태입니다. 동기화 중 참조 대상이 아직 도착하지 않은 메모도 숨기지 않습니다.
- 태그는 정규화한 문자열 배열로 메모에 저장합니다. 별도 `Tag`/`NoteTag` 엔티티 없이 폴더를 넘나드는 태그 검색을 제공합니다. 같은 이름은 소문자로 정규화하고 중복 제거합니다.
- 사용자 지정 날짜는 Gregorian `YYYY-MM-DD`로 저장합니다. 작성/수정 시각은 `Date`입니다.
- 삭제는 표시만 바꾸는 소프트 삭제입니다. 하위 가지는 같은 삭제 묶음 ID를 갖습니다. 이전에 따로 삭제한 자식까지 부모 복구로 되살리지 않습니다.
- 휴지통은 자동 만료하지 않습니다. 영구 삭제 기능은 현재 제공하지 않습니다.
- 편집할 때마다 로컬 저장을 시도합니다. 편집 기록은 같은 편집기의 30초 구간 단위로 묶습니다. 빠른 입력은 열린 입력창 하나를 한 기록으로 묶습니다. 새 편집기/다른 기기는 별도 기록을 만듭니다.
- 본문은 가장 최근 기록의 시각을 기준으로 표시하고 같은 시각이면 UUID로 일관된 순서를 정합니다. 기기 시계가 잘못되면 기대와 다른 기록이 최신으로 보일 수 있으며, 기록 화면에서 다른 버전을 복구할 수 있습니다.
- 트리 구조에 대한 동시 편집은 자동 병합을 보장하지 않습니다. 순환이 생겨도 무한 탐색하지 않으며, 이동 메뉴에서 최상위로 옮겨 복구할 수 있습니다. 실제 CloudKit 동시 편집 검증이 필요합니다.
- 내보내기는 읽을 수 있는 텍스트 백업입니다. 자동 가져오기나 완전한 데이터베이스 복원을 제공하지 않습니다.

## 범위와 남은 검증

iCloud는 사용자 요청에 따라 기본 비활성 상태입니다. 설정 경로는 구현했으며 실제 계정/컨테이너 등록은 [iCloud 설정 안내](docs/ICLOUD_SETUP.md)를 따라 진행합니다.

수동 테스트와 출시 전 항목은 [검증 체크리스트](docs/VALIDATION.md)에 있습니다. 상태 관리, 관련 메모, 자유 배치 캔버스, AI, 위젯, 전역 단축키, 결제는 기획의 후속 업데이트 범위로 남겨 두었습니다.

이 버전은 개인용 초기 데이터 규모에 맞춰 전체 메모와 편집 기록을 조회합니다. 기록 수가 많아지면 입력/검색 성능을 측정하고 조회 범위와 기록 보존 정책을 개선해야 합니다. 로컬 저장은 매 입력마다 동기적으로 수행하므로 장문·대량 메모 성능 테스트도 필요합니다.
